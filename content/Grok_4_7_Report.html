비용은 각 평가에서 실제 사용한 토큰을 공개 API 가격으로 계산한 평균값이다. 일반 추론 비용과 CursorBench 비용은 서로 다른 종류의 작업이므로 같은 열 안에서 모델끼리 비교하는 용도로 보는 것이 정확하다.

Grok 4.7 vs GPT-5.6 Sol Max

  • 종합: 56 vs 55 — 거의 같은 급.
  • 실제 코드 수정: 73% vs 72% — 비슷.
  • 코드베이스 이해: 63% vs 54% — Grok 우위가 큼.
  • 터미널: 33% vs 37% — Sol이 우위.
  • 효율: $8.82 / 39.2분 vs $6.35 / 20.6분 — Grok Build 쪽이 더 비싸고 느림.

Grok 4.7 vs GPT-6 Astra Max

  • 코드 수정: Grok 73% > Astra 68%.
  • 코드베이스 이해: 63% ≈ 62%.
  • 터미널: Grok 33% < Astra 56%.
  • 종합: Grok 56 < Astra 62.
  • 해석: Grok의 부족한 부분은 방향 설정보다 복잡한 실행·도구 운용 쪽에 더 가깝다.

이 표는 모델만 단독으로 시험한 것이 아니라 Grok Build, Codex, Claude Code 같은 각 회사의 코딩 도구와 함께 사용한 결과다. 따라서 모델 성능뿐 아니라 도구의 파일 탐색·명령 실행 방식도 점수, 비용, 시간에 영향을 준다.

세부 성능 비교

강점
  • 방향 설정이 강하다. 장기 업무, 여러 단계 작업, 코드베이스 이해 평가가 모두 높다.
  • 모호한 대규모 코딩에 강하다. CursorBench에서 High/xHigh가 Sol Max보다 높은 점수를 기록한다.
  • 패치 구현도 강하다. 실제 코드 수정 평가가 73%로 비교군 최상단이다.
  • 자기 검증 성향이 개선됐다. 판단 신뢰성과 장기 작업 평가가 4.6보다 좋아졌다.
  • 토큰 단가는 낮다. 기본 API 단가는 입력 $2/M, 캐시 입력 $0.5/M, 출력 $6/M으로 Sol보다 낮다.
약점
  • 토큰을 많이 쓴다. xHigh 일반 평가에서 작업당 출력 81K, Grok Build에서 작업당 14.3M 토큰.
  • 실제 수행 시간이 길다. Grok Build 기준 39.2분/task.
  • 터미널·도구 운용은 상대적으로 약하다. Astra/Fable 최상위와 큰 차이가 난다.
  • 순수 난제 추론은 Sol Max급이 아니다. HLE 기준 Sol Medium~Terra Max 구간.
  • 긴 문맥 처리 자체는 최상위가 아니다. 500K 최대 컨텍스트이며 긴 문맥 평가도 GPT/Claude 1M 계열보다 낮다.
